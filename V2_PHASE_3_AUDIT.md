## A. Original planned scope

Per `04_CLIENT_INTERFACE.md`, Client has 5 dock destinations (Home, Markets, Trade, Services, Me), each with a finalized information architecture: Home's Hybrid Financial Command Hub (hero + journey map + branching journey structure + market panel + quick actions + 11 named modules), Markets' 6-panel Market Hub with pre-connection gating and Focus/Immersive chart behavior, Trade's Practice|Live segmented experience with a 4-panel Practice mode (incl. F&O payoff simulator) and SMC-gated Live mode, Services' hero+3-category+My-Applications hybrid architecture with platform-specific Loans journeys, and Me's 7-flat-category fixed-chrome profile/settings screen. All five screens share the Adaptive Hybrid Stage (Overview/Focus/Immersive) and the app-wide Fully Customizable (Option C) personalisation model, except Me which is a documented, deliberate exception to personalisation.

## H. Bugs, inconsistencies, and technical problems

### H-2. Immersive mode is structurally unreachable from every Client-role screen (new finding, confirmed, distinct from Phase 2's H-1)

**Mechanism.** `app.js:117` derives stage mode as `route.panel ? 'immersive' : focusState.mode` — Immersive mode is entered only when the URL hash has a third segment (`#/<role>/<destination>/<panelId>`), which in turn is only ever set by a `TwmRouter.navigate(role, destination, panelId)` call with all three arguments. A repo-wide search (`grep -rn "navigate(" scripts/ | grep -v router.js`) shows this 3-argument call exists in exactly two files — `employee.js:103` and `admin.js:39,160` — and never once in `client.js`. Every Client panel's interactive affordance instead calls `window.TwmSetFocus('focus', panelId)` ([client.js:106,172,199](scripts/content/client.js#L106)), which can only ever set `focusState.mode` to `'focus'`, never trigger a panel-level route change. There is no code path, anywhere in Client, that can produce a 3-segment hash.

**Verification.** [verify_client_immersive.js](V2_AUDIT_EVIDENCE/verify_client_immersive.js), full output [client_immersive_verification.txt](V2_AUDIT_EVIDENCE/client_immersive_verification.txt), screenshot [client_immersive_mechanism_check.png](V2_AUDIT_EVIDENCE/screenshots/client_immersive_mechanism_check.png). Clicking the Markets watchlist panel (`/client/markets`'s only interactive affordance) changes the stage class to `twm-stage--focus` and leaves the URL hash completely unchanged (`#/client/markets`, no third segment) — confirming the UI never attempts to go further than Focus. Manually forcing the hash to `#/client/markets/watchlist` *does* correctly produce `twm-stage--immersive` and minimize the dock — confirming the underlying Phase 2 stage/router mechanism itself is sound (already credited as WORKING in `V2_PHASE_2_AUDIT.md`) — but nothing in Client's own code ever constructs such a URL.

**Classification implication.** Each of the four per-screen Immersive requirements (Markets P3-21, Trade P3-32, Services P3-44, Me's immersive flows) is classified NOT IMPLEMENTED in Section E above, rather than IMPLEMENTED BUT NOT CONNECTED, because in three of the four cases (Trade, Services, Me) the promised Immersive *content* also does not exist even in isolation — it is not simply a wiring gap. Markets is the closest to a pure wiring gap (content would still need a chart), but is grouped with the others for consistency since the net user-facing outcome — Immersive is never reachable, from any Client screen, under any sequence of normal clicks — is identical across all four.

**Fix location (not applied — audit only, per Step 7):** either give each panel that should support Immersive drill-down an explicit "expand to full view" affordance inside its Focus-mode render that calls `TwmRouter.navigate(role, destination, panel.id)`, or document Immersive as a deliberately Employee/Admin-only pattern if that is in fact the owner's intent — the current state is silent on which of these is correct, which is itself the gap.

### H-3. `smcConnected` has no Disconnect path anywhere in the app (minor, confirmed)

Three screens (Markets' Watchlist, Trade's Live mode, Me's Linked Accounts) read the shared `smcConnected` boolean, and the spec explicitly calls this "the same Connect/Disconnect pattern" (`04_CLIENT_INTERFACE.md` Me §3). `grep -n "disconnect" scripts/content/client.js` returns zero matches. Once connected in a session, there is no way to return to the not-connected state through the UI — only half the named pattern exists. Logged here rather than in Section D because it is a one-line, unambiguous absence rather than a partial implementation with nuance.
