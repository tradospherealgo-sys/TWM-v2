## A. Original planned scope

Per `MASTER_PROMPT.md` §12, Phase 6 is exactly this checklist:
1. All three roles share one design system.
2. Each role remains clearly differentiated.
3. Dock behaviour is consistent.
4. Adaptive Hybrid Stage works across screen sizes.
5. No permanent sidebar has appeared.
6. No invented data, claims or capabilities exist.
7. All important controls have meaningful states.
8. Open decisions remain labelled as open.

`10_SCREEN_INVENTORY.md:50` additionally contains a pre-existing claim: *"The responsive consistency review is complete (confirmed 2026-11-11): a Phase 6 audit found no contradictions across the Adaptive Hybrid Stage wording, dock behaviour, personalisation exceptions, or non-hallucination rules."* This claim is itself audited in section H below — it is a **planning-document** assertion about spec-wording consistency, not a test of the running prototype, and this audit treats it as a claim to verify rather than a substitute for independent testing.

## H. Bugs / inconsistencies / technical problems

1. **H-1 (consolidated, cross-role) — stale `focusState` is not reset on ordinary navigation paths, with 5 confirmed reproduction paths spanning all three roles and the Admin-only cmdk layer.** This bug was first found in Phase 2 and is the single most consequential defect found in the whole audit, because it recurs through every major navigation mechanism in the shared shell:
   - Repro 1 (Phase 2): direct hash edit while focused.
   - Repro 2 (Phase 2): Immersive-mode panel route back-navigation.
   - Repro 3 (Phase 2, Admin-specific): focus a panel in `/admin/team`, open ⌘K, navigate to Compliance — the new screen's first panel renders `opacity:0.2; pointer-events:none` and a real click on it times out (`cmdk_focus_bug_verification.txt`). This is reproduced again this session in the exact same form via the Phase 6 cmdk test, confirming it is still live and not fixed.
   - Repro 4 (Phase 2, Client-specific): ordinary SMC-connect button click bubbles into the parent panel's own click listener, silently calling `TwmSetFocus('focus','watchlist')`.
   - Repro 5 (Phase 2): Kanban/cascade-style multi-panel interaction leaves the UI in a dimmed, unrecoverable state without a full reload.
   This is logged once, consolidated, here, because Phase 6's explicit job is cross-role regression review and this is the one defect that is *provably* cross-role (it has independently reproduced in Client and Admin content, through three different entry mechanisms — Dock, direct hash, and the Admin-only ⌘K layer — all converging on the same root cause: `focusState` at [app.js:86-90](scripts/app.js#L86-L90) is a bare module-level variable, reset only by Dock's `onSelect` callback at [app.js:121-124](scripts/app.js#L121-L124), and by nothing else). The one navigation path confirmed this session to **not** reproduce it is the dev-only role-switch dropdown (P6-08 above) — but that is because switching role always calls `TwmRouter.navigate()` to a different role's first destination, not because the underlying state bug was fixed.
2. **New this phase — Admin's command palette input field is decorative, not functional** (see C, P6-11).
3. **New this phase — Admin's 6-item dock clips at phone width while Client/Employee's 5-item docks do not** (see D, P6-12). This is the one genuine "Dock behaviour is consistent" checklist failure found: the *mechanism* is shared and consistent (P6-03), but its *rendered result* diverges by role at the phone breakpoint because nothing in the dock's CSS adapts item width/count to available space.
